# Method: transact_error()

[Turkce Dokumantasyon](TR-Method-transact_error) | [English Documentation](Method-transact_error)

> **Category:** Transaction & Concurrency Methods  
> **Submodule:** `AmberDB::Transact`  
> **Entry Type:** Error Logging & Immediate Rollback

---

## 1. Definition and Overview

`transact_error($file_path, $message)` is an **internal engine method** that records physical file access and write errors during database operations.

Its decision rule is single and unambiguous:
- If `$file_path` corresponds to a base data table (matching the configured `.$db_ext`, typically `.db`) and the table is not marked with `no_transact => 1`, it **immediately executes `transact_rollback()`**, reverting all mutations in reverse LIFO order, releasing all Strict 2PL locks, and removing the `.txn` journal.
- If the file extension is a secondary index or log (`.inx`, `.src`, `.fld`, `.fac`, `.slg`, `.aut`, `.del`, etc.), the error is logged into the error registry without triggering a rollback (`no_rollback = 1`).

> [!NOTE]
> For **operational / business logic** failures (such as insufficient inventory, insufficient user balance, or client cancellations), do not call `transact_error()`; instead call **`$adb->transact_rollback()`** directly. `transact_error()` is strictly reserved for storage I/O and low-level write integrity.

---

## 2. Syntax and Signature

```perl
$adb->transact_error($file_path, $message);
```

### Parameters
- **`$file_path`** *(String, Required)*: Physical file path where the error occurred (e.g. `"$table_path.$adb->{db_ext}"` or `"$table_path_0.fld"`).
- **`$message`** *(String, Required)*: Low-level error description generated by the engine (e.g. `"Could not open file to write"`).

---

## 3. Practical Code Example (Business Logic vs. Engine Errors)

```perl
$adb->transact_start();

my @product = $adb->read_id("catalog_product", $product_id);
my $current_stock = $product[8];

# 1. Operational condition: Insufficient stock triggers direct transact_rollback()
if ($current_stock < $quantity) {
    $adb->transact_rollback();
    return { success => 0, error => "Out of stock" };
}

# 2. Normal execution: CRUD operations (insert_id, modify_id, etc.)
# If disk space exhausts, flock fails, or table file cannot be written, the engine
# automatically invokes transact_error($file_path, ...) and rolls back immediately.
$product[8] -= $quantity;
$adb->modify_id("catalog_product", @product);
$adb->insert_id("orders", 0, $user_id, $product_id, $quantity, time());

# 3. If clean, finalize and commit changes:
my $txn = $adb->transact_end();
if ($txn->{status} eq 'commit') {
    return { success => 1, message => "Order successfully placed" };
}
```
